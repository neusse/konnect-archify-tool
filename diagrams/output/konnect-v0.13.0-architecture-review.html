1. Consolidate verified schematic commit mechanics

Component commit sequence · Sheet commit sequence · Bounded pilot

Before · observed release structure
Component module: validate → commit → reload
Sheet module: validate → commit → reload
Each handles uncertain readback
After · candidate interpretation
Component validator · Sheet validator
↓
One deep commit/readback module
↓
Refusal / committed / uncertain evidence

Problem: Component and sheet modules repeat the safety sequence while their domain validation differs.

Deepening: Give common sequencing one deep internal module; keep both domain-specific validators local.

  • Locality: one safety sequence
  • Leverage: two real callers
  • Tests cross the same interface
Deletion test: Deleting a forwarding module only moves code; deleting a useful deep module would restore duplicated sequencing in both callers.

Evidence to earn the change: Exercise pre-commit refusal and post-commit uncertain readback for both kinds of change; preserve the bounded outcome pilot rather than migrate every tool.

This is shared mechanics, not a new universal transaction framework.

After · candidate interpretation
Planner · scoring tool

Problem: In-memory planning re-enters a public tool handler through disk I/O and MCP-response decoding.

Deepening: Deepen the shared scoring and transform computation so both planning and tool handling use it directly.

  • Locality: one scoring implementation
  • Leverage: no temporary scoring I/O
  • Tests exercise domain computation
Deletion test: Deleting the current detour is useful only if one shared computation remains; duplicating score or transform logic would lose the existing consistency guarantee.

Evidence to earn the change: Assert score equality and preview/apply transform equality on existing KiCad-authored fixtures; retain no-write planning and the existing outline refusal.

No autonomous placement expansion, optimizer replacement or additional geometry support.

3. Keep exact board selection local to composite operations

Implicit item read · Explicit item read · Composite document selection · Source selection

Before · observed release structure
Caller carries client + document + path
Chooses implicit or explicit read each time
Repeated target knowledge
After · candidate interpretation
Composite operation selects exact board once
↓
A target-scoped module owns repeated reads
↓
General client stays internal

Problem: Composite callers must repeatedly choose between implicit-current-board and target-explicit client methods.

Deepening: Explore a narrow module that retains exact board selection for the duration of one composite operation.

  • Locality: target selection once
  • Leverage: repeated reads stay scoped
  • Tests detect wrong-document reads
Deletion test: A module that only forwards client methods is shallow; it must own target selection across the entire operation.

Evidence to earn the change: Use multiple open-board identities in deterministic tests; assert each read targets the requested document.

There is one production IPC adapter. Do not introduce a generic transport interface merely because tests use mocks.

Deepening: Explore one reconciliation module owning managed files, client hooks, markers and desired/effective/partial state.

  • Tests cover lifecycle round trips
Deletion test: Depth exists only if deleting the module would restore multiple inventories and state interpretations; moving three implementations unchanged adds nothing.

Evidence to earn the change: Install/status/uninstall round trips and partial hook failures in temporary directories, preserving the release's notification and customization policy.

5. Give footprint transforms one semantic owner

Move dispatch · Rotation dispatch · Flip dispatch · Saved-file transforms · Hybrid execution

Before · observed release structure
Move handler chooses IPC / saved file
Rotate handler chooses IPC / saved file
Flip handler chooses IPC / saved file
After · candidate interpretation
One user-directed transform module
↓
KiCad IPC adapter · saved-file adapter
↓
Capability differences remain explicit

Problem: Move, rotate and flip semantics are spread across handler branches for two actual execution adapters.

Deepening: Explore one owner for operation meaning, retaining each adapter's supported mutation and observed-result contract.

  • Locality: transform semantics together
  • Leverage: three operations share meaning
  • Tests compare two real adapters
Deletion test: A module that only selects a path adds no depth; it must absorb repeated operation semantics without hiding real adapter differences.

Evidence to earn the change: Compare observed results on asymmetric KiCad-derived fixtures through both supported paths; retain unsupported-case refusals and live-board file-write safety.

Two real adapters justify this seam: KiCad IPC and saved-board S-expression handling. This is not autonomous layout, routing or manufacture management.

Top recommendation · risk leverage

Verified schematic commit mechanics

Repeated safety sequencing has the greatest leverage against the “fix here, regress elsewhere” cycle; first prove the two callers share the same invariant before consolidating it.

For a smaller initial change, candidate 2 removes a concrete computation detour without broadening feature scope. “Strong” describes source evidence for that detour; it does not automatically outrank safety leverage.

Method and limits

Used the improve-codebase-architecture and codebase-design approach: recent-change hotspots, depth, deletion tests, actual callers/adapters and tests at the same interface. Review focused on IPC targeting, schematic mutation, guidance installation, placement computation and footprint transforms.

The release has no GLOSSARY.md or docs/adr/ directory. Existing architecture and reliability documents were consulted; no absent ADRs were invented. Large-file size alone is not a finding, and no general rewrite is recommended.

Actual Windows validation: formatting, workspace library/tests and doctests passed. Strict all-target clippy failed on a platform-gating mismatch for an unused test constant. Live IPC, full real-KiCad E2E and benchmark were not rerun. See the quality report's evidence table.

Existing shared board-source selection and config persistence improvements are recognized, not proposed again. Manufacturing capability truth and malformed-field refusal are correctness follow-ups in the separate report, not excuses for architectural expansion.
