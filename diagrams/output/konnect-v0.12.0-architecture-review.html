Problem

Five mutation families rebuild read → plan → validate → persist → readback → uncertainty, so recent fixes repeatedly cross the same seam.

Solution

Keep domain planning in handlers; move persistence, conflict classification, committed readback, recovery, and common evidence behind one deep module.

Deletion test

Deleting it would spread the complete lifecycle back across at least five callers. Complexity concentrates rather than vanishes.

Wins

  • Locality: conflicts have one owner
  • Leverage: every mutation benefits
  • One interface is the test surface
  • Single and batch stop drifting

After · policy drives one deep module

Problem

ToolDef::board_access describes policy, but handlers separately choose live IPC, fallback, or refusal. Metadata and behavior can disagree.

Solution

Let the declaration drive one board-operation module. Live IPC and guarded saved-file access are two real adapters at one justified seam.

Deletion test

Today deleting BoardAccess removes guidance but not safety behavior: it is shallow. Deepening makes deletion spread target and fallback policy everywhere.

Wins

  • One policy source
  • Locality: wrong-board fixes concentrate
  • Leverage across every PCB tool
  • Catalogue-wide conformance tests

Problem

Declared inputs are reinterpreted by handlers, and most results are hand-serialized. The same contract exists in several places.

Solution

Deletion test

Argument helpers already pass: deletion duplicates parsing hundreds of times. Deepen the enclosing module so callers stop maintaining the contract twice.

Wins

  • One interface for deployed tests

Problem

Unified review calls private handlers, extracts response text, parses it back to JSON, then calculates coverage and verdict.

Solution

Own audits, diagnostics, evidence coverage, and verdict in a typed module. MCP tools become rendering adapters.

Deletion test

Current handler-to-handler adapters are shallow. Deleting a typed engine would spread verdict rules across every review-facing caller.

Wins

  • One verdict owner
  • Typed findings are the test surface
  • No response re-parsing
  • Unavailable evidence stays visible

After · one concrete deep catalog

KiCad library catalog module

Problem

library.rs is deep overall, but catalog policy has low locality across table, environment, project, search, and consumer code.

Solution

Extract one concrete internal catalog module that owns resolution and provenance. Keep symbol and footprint builders as separate implementations.

Deletion test

The whole file passes; size alone is not the defect. The catalog portion earns depth when deletion spreads resolution policy back across consumers.

Seam discipline: do not invent a trait merely to split the file. One adapter is hypothetical; add an interface only when a second catalog adapter exists.

Wins

  • Resolution policy gains locality
  • Provenance has one owner
  • Builders consume one catalog
  • Search and placement stop drifting

Top recommendation

Deepen schematic mutation execution

It is the clearest concentration of v0.12.0 churn, has a bounded migration path, and makes the interface the test surface for the exact failure class Konnect has repeatedly repaired: refusal, persistence, readback, uncertainty, and recovery.
