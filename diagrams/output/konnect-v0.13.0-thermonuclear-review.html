Spec

Do shipped behaviors match advertised capabilities and issue acceptance? Three source-supported gaps; no runtime reproductions of these three were executed.

Coverage contract mismatchSource confirmed

S1 · Manufacturing audit promises more than it checks

The tool advertises component spacing, via-in-pad, acid traps, board-outline issues and silkscreen overlap. Its implementation checks outline presence, two-sided assembly, silkscreen overlap and configured minimum trace width. It does not perform the first three advertised checks.

run_design_review includes this audit and can report “LOOKS GOOD” without those categories being checked. Native KiCad DRC is also run when available, but that does not make the claimed custom DFM coverage true.

Smallest coherent fix: narrow the tool description and publish explicit checked / not-checked categories. Do not build a new manufacturing-rules engine to satisfy an overbroad description.

Advertised checks · Actual implementation · Review inclusion · Review verdict
Additional outline weakness: content.contains("Edge.Cuts") at line 521 can match a layer declaration rather than outline geometry. No focused issue was identified by the targeted search; #184 addresses a different coverage/extraction gap.

Known open acceptance gapSource confirmed

S2 · Cost estimates are still rough averages

The component estimate uses footprint count × $0.05 for JLCPCB or × $0.08 for PCBWay. It does not use part-specific LCSC/JLCPCB prices or Extended-part fees requested by #793. Its guidance recommends generate_bom, which is not a registered tool.

The result already carries approximation/BETA disclaimers; this is an incomplete accepted feature, not a hidden claim of a firm vendor quotation.

Smallest coherent fix: correct the nonexistent-tool advice immediately. Resolve #793's scope explicitly: bounded price evidence or an honest unsupported/referral result, not unlimited procurement ownership.

Cost handler · Fixed averages · Disclaimer and absent-tool advice
Expected discriminator: equal footprint counts with different priced parts cannot affect this implementation's component estimate.

Malformed-input safety gapSource path confirmed; not reproduced

S3 · Rotation can skip malformed field placement

A property with an unparseable (at …) survives parsing. map_field_positions skips it, while the public rotation handler rotates the body, writes the candidate and reports successful readback.

This does not establish failure on ordinary valid KiCad schematics. It is a narrow malformed-input path, and it conflicts with the documented preflight and malformed-evidence contract.

Smallest coherent fix: validate affected field placements before mutation and refuse without writing. Reuse the existing sibling field-placement refusal; do not add a repair/recovery subsystem.

Property parsing · Silent skip · Public rotate/write/readback · Input, mutation and evidence requirements
#612/#614 cover valid field carry. Targeted search found no dedicated malformed-field issue. Future regression: alter one field token in a KiCad-authored fixture; assert structured refusal and byte-identical file.

Maintainability observations · not hard violations

  • Raw JSON/MCP results remain coupled to domain transformations in several large tool modules.
  • Schematic edits still span structural editing and text-preserving operations; consolidate repeated mutation invariants rather than rewrite both representations.
  • Placement planning re-enters tool handlers through temporary files. Reuse one computation implementation directly without losing preview/apply consistency.
  • Manufacturing profiles remain hard-coded; supported coverage should be explicit.
  • Rotation fixtures have documented KiCad 10.0.6 provenance and independent CLI oracles. Custom-field and real multi-unit field-rotation observations remain useful when extending this operation, not a mandate to test every imaginable variant now.
